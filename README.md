# Coffee Point

Лендинг кофейни с серверной частью (Node.js + Express), ИИ-чат-ботом на OpenAI
и личным кабинетом с базой знаний для администратора.

```
├── server/
│   ├── index.js       # Express: статика, /api/chat, /api/auth/*, /api/knowledge
│   ├── context.js     # База знаний по умолчанию (меню, цены, контакты, правила)
│   ├── knowledge.js   # Та же база, но редактируемая админом (data/knowledge.json)
│   └── users.js       # Пользователи, хеши паролей, сессии
├── public/
│   ├── index.html     # Лендинг + виджет чата
│   ├── account.html   # Личный кабинет
│   ├── style.css
│   ├── script.js      # прежнее поведение лендинга
│   ├── chat.js        # клиент чата
│   ├── auth.js        # общие запросы аутентификации
│   └── account.js     # клиент кабинета
├── data/               # users.json, knowledge.json (не в git)
└── .env                # секреты (не в git)
```

## Запуск

```bash
npm install
cp .env.example .env    # и впишите свои значения
npm start               # http://localhost:3456
```

При первом запуске из `ADMIN_LOGIN`/`ADMIN_PASSWORD` (или
`admin`/`admin123`, если переменные не заданы) создаётся администратор. Клиенты
регистрируются сами: «Кабинет» в навбаре → «Регистрация».

### Переменные окружения

| Переменная       | По умолчанию  | Назначение                                   |
| ---------------- | ------------- | -------------------------------------------- |
| `OPENAI_API_KEY` | —             | Ключ OpenAI. Без него ИИ отключён.            |
| `OPENAI_MODEL`   | `gpt-4o-mini` | Модель chat.completions.                      |
| `PORT`           | `3456`        | Порт HTTP.                                    |
| `ADMIN_LOGIN`    | `admin`       | Логин администратора кабинета.                |
| `ADMIN_PASSWORD` | `admin123`    | Пароль администратора (смените!).             |
| `MAX_MESSAGES`   | `20`          | Размер контекстного окна (реплик).            |
| `RPS_LIMIT`      | `20`          | Запросов в минуту на IP (чат, вход, регистрация). |

## Личный кабинет

`/account`, вход по имени и паролю. Сессия — HTTP-only cookie; роль
сервер всегда берёт из своей записи о пользователе, подделать её со стороны
браузера нельзя.

**Клиент:** профиль (логин, роль, выход) и чат на сайте.

**Администратор:** то же плюс вкладка «База знаний» — правите текст секций,
нажимаете «Сохранить», и `data/knowledge.json` подменяет значения из `context.js`
для каждого следующего вопроса бота. Значения по умолчанию всегда в `context.js`:
удалите `data/knowledge.json`, и сайт вернётся к ним.

## Как это работает

1. Браузер собирает историю реплик и шлёт `POST /api/chat`.
2. Сервер срезает окно до `MAX_MESSAGES`, берёт system prompt
   (`knowledge.buildSystemPrompt()` — файл админа, а иначе дефолты `context.js`)
   и спрашивает модель.
3. Ключ OpenAI живёт только на сервере.

### Поведение вне темы

Модель должна на вопрос не про кофейню отвечать меткой `[[OUT_OF_SCOPE]]`;
сервер ловит её и подменяет ответ дефолтным.

## API

| Метод | Путь | Доступ |
| ----- | ---- | ------ |
| `GET` | `/api/health` | все |
| `POST` | `/api/chat` | все |
| `POST` | `/api/auth/login` | все |
| `POST` | `/api/auth/register` | все |
| `POST` | `/api/auth/logout` | все |
| `GET` | `/api/auth/me` | все |
| `GET` | `/api/knowledge` | админ |
| `PUT` | `/api/knowledge` | админ |

Пример `POST /api/chat`:

```json
{ "messages": [ { "role": "user", "content": "цена капучино?" } ] }
```

```json
{ "reply": "Капучино — 650 ₸ …" }
```

Ошибки: `400` при некоррекном теле, `401` без входа, `403` для чужой роли,
`409` при пересечении логина, `429` при лимите, `502` при неверном ключе OpenAI.
Таймауты OpenAI деградируют в `200 { "reply": …, "degraded": true }`.
