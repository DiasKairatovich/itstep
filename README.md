# Coffee Point

Лендинг кофейни с серверной частью (Node.js + Express), ИИ-чат-ботом на OpenAI
и базой знаний: администратор загружает документы, и бот отвечает гостям по ним.

```
├── server/
│   ├── index.js       # Express: статика, /api/chat, /api/auth/*, /api/knowledge, /api/documents
│   ├── context.js     # База знаний по умолчанию (меню, цены, контакты, правила)
│   ├── knowledge.js   # Та же база, но редактируемая админом (data/knowledge.json)
│   ├── rag.js         # Документы: фрагменты, векторы, косинусное сходство
│   └── users.js       # Пользователи, хеши паролей, сессии
├── public/
│   ├── index.html     # Лендинг + виджет чата
│   ├── account.html   # Личный кабинет
│   ├── admin.html     # Страница документов базы знаний
│   ├── style.css
│   ├── script.js      # прежнее поведение лендинга
│   ├── chat.js        # клиент чата
│   ├── auth.js        # общие запросы аутентификации
│   ├── account.js     # клиент кабинета
│   └── admin.js       # клиент страницы документов
├── eval/               # вопросы для самопроверки: node eval/run.js
├── sample_docs/        # два тестовых документа
├── data/               # users.json, knowledge.json, rag.db (не в git)
└── .env                # секреты (не в git)
```

## Запуск

```bash
npm install
cp .env.example .env    # и впишите свои значения
npm start               # http://localhost:3456
```

При первом запуске из `ADMIN_LOGIN`/`ADMIN_PASSWORD` (или
`admin`/`admin123`, если переменные не заданы) создаётся администратор. Клиенты
регистрируются сами: «Кабинет» в навбаре → «Регистрация».

### Переменные окружения

| Переменная       | По умолчанию  | Назначение                                   |
| ---------------- | ------------- | -------------------------------------------- |
| `OPENAI_API_KEY` | —             | Ключ OpenAI. Без него ИИ отключён.            |
| `OPENAI_MODEL`   | `gpt-4o-mini` | Модель chat.completions.                      |
| `PORT`           | `3456`        | Порт HTTP.                                    |
| `ADMIN_LOGIN`    | `admin`       | Логин администратора кабинета.                |
| `ADMIN_PASSWORD` | `admin123`    | Пароль администратора (смените!).             |
| `MAX_MESSAGES`   | `20`          | Размер контекстного окна (реплик).            |
| `RPS_LIMIT`      | `20`          | Запросов в минуту на IP (чат, вход, регистрация). |

База знаний (всё опционально, `data/rag.db`):

| Переменная           | По умолчанию        | Назначение                                        |
| -------------------- | ------------------- | ------------------------------------------------- |
| `EMBEDDING_MODEL`    | `text-embedding-3-small` | Модель эмбеддингов; ключ общий с ботом.              |
| `RAG_TOP_K`          | `4`                 | Сколько фрагментов попадает в промпт.               |
| `RAG_MIN_SIMILARITY` | `0.3`               | Ниже — бот отвечает «не знаю» и не зовёт модель.     |
| `CHUNK_SIZE`         | `600`               | Целевая длина фрагмента в знаках (800 — потолок).    |
| `CHUNK_OVERLAP`      | `100`               | Перекрытие соседних фрагментов в знаках.             |

## База знаний: документы

`/admin` — страница входа администратора: загружает `.txt`/`.md` (до 1 МБ),
показывает список документов, позволяет переиндексировать и удалить файл
вместе с его фрагментами.

1. Файл режется на фрагменты по ~600–800 знаков с перекрытием в 100, резы
   идут по абзацам и предложениям.
2. Каждый фрагмент получает вектор `text-embedding-3-small` (пачками), вектор
   лежит BLOB'ом в той же базе, что и документы.
3. Вопрос гостя превращается в такой же вектор, находятся 4 ближайших фрагмента.
   Лучшие из них попадают в system prompt, а их названия бот показывает
   под ответом как «Источники».
4. Если лучшее сходство ниже `RAG_MIN_SIMILARITY`, бот отвечает `NO_ANSWER` и
   модель не вызывает. Формулировка выбрана для гостя: без терминов «база
   знаний» и RAG — посетитель о них не знает и принял бы отказ за поломку.

Текст документа для модели — данные: инструкция в промпте требует игнорировать
любые пожелания, встреченные внутри фрагментов.

> Пока в базе нет ни одного документа, бот отвечает как раньше — по разделам
> из `context.js`/`knowledge.json`. Загрузите первый файл, и дальше бот
> опирается на них; меню, цены и контакты тоже стоит занести документом.

### Самопроверка

```bash
node eval/run.js          # вопросы из eval/questions.json через /api/chat
```

Скрипт индексирует `sample_docs/`, поднимает сервер на свободном порту и
печатает вопрос, ответ и источники. В `questions.json` обычные вопросы имеют
поле `expect` (документ-источник), а ловушки — `"trap": true`: бот обязан
признаться, что ответа в базе нет.

## Личный кабинет

`/account`, вход по имени и паролю. Сессия — HTTP-only cookie; роль
сервер всегда берёт из своей записи о пользователе, подделать её со стороны
браузера нельзя.

**Клиент:** профиль (логин, роль, выход) и чат на сайте.

**Администратор:** то же плюс вкладка «База знаний» — правите текст секций,
нажимаете «Сохранить», и `data/knowledge.json` подменяет значения из `context.js`
для каждого следующего вопроса бота. Значения по умолчанию всегда в `context.js`:
удалите `data/knowledge.json`, и сайт вернётся к ним.

## Как это работает

1. Браузер собирает историю реплик и шлёт `POST /api/chat`.
2. Сервер срезает окно до `MAX_MESSAGES`, ищет вопрос в базе знаний (`rag.js`:
   эмбеддинг вопроса → 4 ближайших фрагмента по косинусному сходству), берёт
   system prompt (`knowledge.buildSystemPrompt()` — файл админа, а иначе
   дефолты `context.js`), дополняет его найденными фрагментами и спрашивает
   модель.
3. Ключ OpenAI живёт только на сервере: и на чат, и на эмбеддинги.

### Поведение вне темы

Модель должна на вопрос не про кофейню отвечать меткой `[[OUT_OF_SCOPE]]`;
сервер ловит её и подменяет ответ дефолтным. Если же в базе знаний нет
близких к вопросу фрагментов (сходство ниже `RAG_MIN_SIMILARITY`), сервер
обходится без модели вообще.

## API

| Метод | Путь | Доступ |
| ----- | ---- | ------ |
| `GET` | `/api/health` | все |
| `POST` | `/api/chat` | все |
| `POST` | `/api/auth/login` | все |
| `POST` | `/api/auth/register` | все |
| `POST` | `/api/auth/logout` | все |
| `GET` | `/api/auth/me` | все |
| `GET` | `/api/knowledge` | админ |
| `PUT` | `/api/knowledge` | админ |
| `GET` | `/api/documents` | админ |
| `POST` | `/api/documents` | админ |
| `POST` | `/api/documents/:id/reindex` | админ |
| `DELETE` | `/api/documents/:id` | админ |

Пример `POST /api/chat`:

```json
{ "messages": [ { "role": "user", "content": "цена капучино?" } ] }
```

```json
{ "reply": "Капучино — 650 ₸ …", "sources": ["Меню"] }
```

В `sources` — названия документов-источников; пустой список означает, что ответ
собран без базы знаний (или что ответа в базе не нашлось).

Ошибки: `400` при некоррекном теле, `401` без входа, `403` для чужой роли,
`409` при пересечении логина, `413` для файла больше 1 МБ, `429` при лимите, `502` при неверном ключе OpenAI.
Таймауты OpenAI деградируют в `200 { "reply": …, "degraded": true }`.
